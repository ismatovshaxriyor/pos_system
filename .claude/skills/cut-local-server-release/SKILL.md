Extracted from repo-root `CLAUDE.md`'s Licensing → Update rollout section (Phase 5, prod-only). See that section for how Watchtower itself is wired (HTTP-API mode, service scoping, image tagging).

**Cutting a release / verifying rollout:** the reported version (`APP_VERSION`, sent in every heartbeat's metrics) is now read from `local_server/VERSION` (a file baked into the image, `config/settings.py::_read_app_version`) — deliberately *not* from an env var anymore, because a prod `.env` that pinned `APP_VERSION` would keep reporting the old number after Watchtower swapped the image, silently breaking rollout verification (env is only a fallback when the file is unreadable). So a release is three steps, now mostly automated: **(1) build+push the image** — bump `local_server/VERSION`, then push a `v*` git tag (e.g. `v0.1.2`), which fires `.github/workflows/release-local-server.yml` (the *only* CI that builds the local_server/Bola image — the earlier "no local_server CI" note is now stale): it builds the prod image and pushes it to `ghcr.io/<owner>/pos-local:stable` **and** `:<VERSION>` using the built-in `GITHUB_TOKEN` (no extra secret; package is private by default, so each Bola host needs a one-time `docker login ghcr.io` — Watchtower already mounts `~/.docker/config.json`). A `v*` tag push does **not** trigger the cloud deploy (that's filtered to `push: branches: main`). **(2) tell the fleet** — one Ona admin action, `tenants/admin.py::action_release_version` ("⬆️ Tanlangan Bolalarga YANGI VERSIYA yuborish"): select the restaurants, type the version once on the intermediate page, and it sets `desired_version` **and** enqueues `update_app` for every *active* one at once (inactive/blocked restaurants are skipped). The older `action_update_app` (per-restaurant, reads each `desired_version`, blank-skips) is kept for backward-compat. **(3) verify** — rollout is confirmed when a restaurant's heartbeat-reported `app_version` (shown by `RestaurantAdmin.app_version_display`) converges to `desired_version`. Note the whole path only works for a Bola running the **prod** compose (Watchtower lives there, not in dev `docker-compose.yml`); a dev/git-pull machine has no Watchtower and can't receive `update_app`.
